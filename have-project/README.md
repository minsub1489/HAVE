**이 폴더가 개발의 루트입니다.** 문서에서 "저장소 루트"라고 하면 이 폴더를 가리킵니다.

**두 단계로 진행합니다.** 11/30(월) 18시까지는 연락 없이 각자 일하고(1단계), 11/30 저녁에 한 번에 합친 뒤 남은 일을 다시 나눕니다(2단계). 1단계에 지킬 규칙은 가이드라인 8.6에 있습니다. 시작하기 전에 꼭 읽어 주세요.

| 확장 프로그램 `app.js` 분리 | 화면별 파일 11개 + `start.js`. 동작은 1.1.0과 같음 |
| `docs/api.md` | 예시 JSON이 모두 있음. 11/28 고정 |

서비스 · 진입점 · PostgreSQL 저장 구현 · 화면의 서버 연동은 아직 없습니다. 각자 가이드라인 4.4~4.7의 자기 항목을 만듭니다.

**확인한 것**(Linux, JDK 21, Gradle 8.14.3, PostgreSQL 16, Node 22)

- 서버 테스트 17개 통과: 서버 기동, 상태 확인 주소, 404 오류 모양, 해시, 키 정렬 JSON, enum과 CHECK 제약의 일치, `StubPersistence`(자동 번호 · 복합 키 · 조건 · 삭제), 공용 대역(구현이 없을 때만 들어가고 있으면 빠짐)
- 공용 대역을 실제 서버 구성으로도 확인: 다른 서브시스템의 인터페이스를 받는 서비스만 있는 상태에서 서버가 뜨고(대역이 들어감), 진짜 구현을 더하면 그것이 쓰이고 빈이 둘이 되지 않음
- `stub` 프로필로 서버 기동(DB 없음), `jdbc` 프로필로 기동(테이블 31개 · 외래 키 40개 생성, 두 번째 기동에서도 오류 없음)
- 스키마의 제약이 실제로 막는지: 진행 중 검토 요청 1개 제한, 작업마다 검토자 · 최종 승인자 1명, 복합 외래 키, 코드 값 CHECK, 점수 범위
- `app.js`를 나눈 뒤 화면 74개의 출력이 원본과 같고, 등록부터 승인 · 공개 검증 · 철회까지의 클릭 흐름이 원본과 같음
- 확장 프로그램 규칙 테스트 7개 통과

**확인하지 못한 것**

- **Windows에서 `gradlew.bat`으로 실행하는 것.** 위 확인은 같은 버전의 Gradle을 직접 설치한 Linux에서 했습니다. 래퍼가 처음 실행될 때 Gradle을 내려받는 과정은 확인 환경의 네트워크 제한 때문에 끝까지 보지 못했습니다. 처음 받는 사람이 3절대로 해 보고, 안 되면 바로 알려 주세요.
- 실제 Chrome에 확장 프로그램을 설치해 눌러 보는 것. 화면 확인은 `app.html`을 브라우저로 직접 열어 자동으로 했습니다.

## 3. 시작하기

### 3.1 준비

| 필요한 것 | 버전 | 쓰임 |
| --- | --- | --- |
| JDK | **21** (Temurin 21 권장) | 서버. 21이 아니면 빌드되지 않습니다. `java -version`이 21로 나오고 `JAVA_HOME`이 그 JDK를 가리켜야 합니다 |
| Chrome | 최신 | 확장 프로그램 |
| Git | — | |
| PostgreSQL | 16 이상 | `jdbc` 프로필에만 필요. 1단계에는 D만 필요하고 나머지는 12/1까지 없어도 됩니다 |
| Node.js | 18 이상 | 확장 프로그램 규칙 테스트에만 필요 |

Gradle은 설치하지 않습니다. `gradlew`가 처음 실행될 때 내려받습니다(몇 분 걸립니다).

### 3.2 서버 실행

```
cd have-server
gradlew.bat test
gradlew.bat bootRun
```

- macOS · Linux · Git Bash에서는 `./gradlew`를 씁니다. `permission denied`가 나오면 `chmod +x gradlew`를 한 번 실행합니다. PowerShell에서는 `.\gradlew.bat`입니다.
- 브라우저에서 `http://localhost:8080/api/health`를 열어 `{"status":"UP","profile":"stub"}`이 나오면 됩니다.
- 끌 때는 `Ctrl + C`. `stub` 프로필은 DB 없이 메모리에만 저장하므로 서버를 끄면 데이터가 사라집니다.
- 8080 포트를 다른 프로그램이 쓰고 있으면 `gradlew.bat bootRun --args="--server.port=8081"`.

### 3.3 확장 프로그램 열기

1. Chrome 주소창에 `chrome://extensions`
2. 오른쪽 위 **개발자 모드**를 켬
3. **압축해제된 확장 프로그램을 로드합니다** → `have-chrome-extension` 폴더 선택
4. 툴바의 HAVE 아이콘 → `사이드 패널` 또는 `새 탭에서 열기`

지금은 서버를 부르지 않는 로컬 시연 상태라 서버 없이도 열립니다. 시연 계정 비밀번호는 서버 연동 뒤 다섯 계정 모두 `have-demo-1128`입니다(`docs/api.md` 3절). 파일을 고친 뒤에는 `chrome://extensions`에서 새로 고침(↻)을 누릅니다. 규칙 테스트는 `have-chrome-extension` 폴더에서 `node --test tests/model.test.js`.

### 3.4 PostgreSQL로 실행 (`jdbc` 프로필)

PostgreSQL을 설치한 뒤 `psql -U postgres`에서 한 번만:

```sql
CREATE USER have WITH PASSWORD 'have';
CREATE DATABASE have OWNER have;
```

```
cd have-server
gradlew.bat bootRun --args="--spring.profiles.active=jdbc"
```

- 서버가 시작할 때 테이블 31개를 만듭니다(이미 있으면 건너뜀). 접속 값이 다르면 환경 변수로 줍니다: `set HAVE_DB_URL=…`, `set HAVE_DB_USER=…`, `set HAVE_DB_PASSWORD=…`(`.env.example` 참고).
- 스키마 SQL을 고친 뒤에는 이미 만들어진 테이블이 바뀌지 않습니다. 개발 중에는 DB를 지우고 다시 만듭니다: `DROP DATABASE have;` 후 위의 `CREATE DATABASE`.

팀원공유용_v3의 상태 다이어그램 ①과 디자인 패턴 문서 7장을 기준으로 하고,

## 6. 규칙 요약

자세한 내용은 가이드라인 8절과 `AGENTS.md` 4절에 있습니다.

**1단계(11/30 18시까지)**

- 자기 브랜치(`phase1/a` 등)에서만 일하고, 다른 사람의 브랜치를 가져오지 않습니다.
- 자기 패키지 · 자기 파일만 만들고 고칩니다. 공용 파일 목록은 가이드라인 8.6에 있습니다.
- 다른 사람의 인터페이스를 main 코드에서 구현하지 않습니다. 테스트에서 Mockito로 대신합니다.
- 계약에 없는 것이 필요하면 우회하지 말고 메모(`docs/phase1/<담당>.md`)와 `// TODO(통합)`으로 남깁니다.

**언제나**

- 이름은 설계서 그대로. 유스케이스를 늘리지 않습니다. `팀원공유용_v3`를 고치지 않습니다.
- 설계와 달라지면 기록합니다(1단계는 메모에, 2단계는 그 PR에서 `docs/design-changes.md`에).
- 2단계에는 `main`에 직접 올리지 않고 `feat/<담당>-<항목>-<요약>` 브랜치에서 작은 PR로 하루 한 번 이상 합칩니다.
- 비밀번호, DB 접속 값, 서명 키, 업로드된 파일은 올리지 않습니다.
