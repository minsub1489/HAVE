# HAVE의 지식 부채와 이해 확인 설계

2026-11-16 팀 논의. HAVE는 AI 에이전트의 산출물을 채택한 사람이 핵심 판단을 설명하고 검증할 수 있게 하고, 그 근거를 팀에 남겨 다른 사람이 이어서 작업할 수 있게 한다. 검토·승인 증명은 당시 사람이 확인한 파일 버전과 범위를 기록한다.

이 문서에서 **지식 부채**는 팀원이 작업을 설명·수정·재사용하는 데 필요한 이유, 가정, 확인 방법을 찾거나 적용하지 못해 추가로 확인해야 하는 부분이다. AI를 쓰지 않은 작업에도 생기며, 작성자만 아는 근거도 인수인계에서는 부채가 될 수 있다.

## 협업에서 지식이 끊기는 지점

| 문제 | 관찰할 상황 | 설계 대응 후보 |
| --- | --- | --- |
| 근거가 여러 곳에 흩어짐 | 결정 이유는 채팅에 있고, 수치의 출처는 별도 파일에 있으며, 어떤 버전에 사용됐는지 찾기 어렵다. | 작업 상세에서 관련 결정·가정·확인 방법과 원본 위치를 버전에 연결한다. 출처가 갱신돼도 판단 당시 참조한 근거를 식별할 수 있게 한다. |
| 핵심 지식이 한 사람에게 집중됨 | 담당자가 빠지면 팀원이 작업을 설명하거나 수정할 수 없다. | 영향이 큰 부분은 인수받을 팀원을 정하고, 그 사람이 근거만으로 후속 작업을 해 보게 한다. |
| 팀원마다 다른 가정을 사용함 | 예산 담당자는 500명, 배포 담당자는 1,000명을 같은 계획의 전제로 쓴다. | 각 가정의 적용 대상과 출처를 보여주고, 충돌을 질문으로 남겨 합의한 결과와 영향을 받는 작업을 연결한다. |
| 변경으로 이전 근거의 적용 범위가 달라짐 | v1의 근거는 남아 있지만 v2의 달라진 조건에 그대로 적용할 수 있는지 알기 어렵다. | 참조한 버전·조건을 함께 표시하고, 실제 변경 영향을 받은 근거를 다시 확인한다. |
| 에이전트가 만든 결과의 설명·검증이 빠짐 | 기능은 동작하지만 어떤 조건에서 결과가 달라지는지 작성자가 설명하지 못한다. | 설명과 작은 적용 과제에서 막힌 지점을 기록하고, 보완한 근거가 다른 팀원에게도 쓰이는지 확인한다. |

팀원 모두가 같은 깊이로 모든 영역을 알 필요는 없다. 팀이 공통으로 알아야 할 결정과, 담당 전문가에게 필요할 때 도달할 수 있어야 하는 정보를 구분한다. 해결 우선순위는 변경의 파급 범위, 담당자 부재 시 작업이 멈추는지, 가까운 인수인계·재사용 예정이 있는지로 판단한다. 이해 확인 결과는 작업 범위와 회차에 연결해 보완 대상을 찾는 데 쓰고, 팀원 개인 순위로 집계하지 않는다.

## 사용 흐름

1. **에이전트 작업을 검토한다.** 작성자가 파급이 큰 변경을 골라 `대상 버전과 위치 / 채택 이유 / 가정 / 직접 확인한 근거 / 남은 질문`을 기록한다. 에이전트가 요약과 근거 위치를 제시하면 작성자가 원문, 변경분 또는 실행 결과와 대조한다. 위치는 우선 PDF 페이지·섹션으로 잡는다. 코드로 확장할 때는 커밋과 파일·심볼로 추적한다.
2. **작성자가 이해를 보여준다.** 기본 후보는 근거가 있는 설명 한 개와 적용 과제 한 개다. 위험이 큰 작업은 검토자의 예측 불가능한 후속 질문이나 제한된 사본에서 직접 수정·검증하는 과제를 추가한다. 문항마다 대상 범위, 기대 근거, 확인할 오류를 정한다. 검토자는 표현력이나 답변 길이보다 설명이 참조한 근거, 인과관계, 검증 결과를 본다.
3. **모르는 부분을 해결한다.** 작성자·검토자·인수받는 팀원이 부채 항목을 제기할 수 있다. 담당자가 근거를 보완하면 다른 팀원이 실제로 찾아 설명하거나 적용한다. 근거를 추가한 뒤에도 적용에 실패하면 항목을 다시 연다. 이번 승인에 영향을 주는 문제와 추후 보완 가능한 문제를 판단하는 정책은 팀 합의 대상으로 둔다.
4. **후속 버전에서 변경 영향을 확인한다.** 관련 가정·근거·대상 부분이 바뀌면 해당 항목을 재확인 대상으로 표시한다. 이전 버전의 기록은 추적 가능하게 보존하고 새 버전의 승인과 이해 확인은 해당 범위로 다시 기록한다.

### 과제 선택

| 방식 | 적합한 확인 | 비용 추정표 예시 |
| --- | --- | --- |
| 짧은 퀴즈 | 기본 개념과 파라미터 자가진단 | 월 사용자 수의 영향을 받는 비용 항목을 고른다. |
| Teach-back | 이유·근거·가정 설명 | 왜 월 사용자 500명을 기준으로 삼았는지 출처와 적용 한계를 설명한다. |
| Fault Injection | 오류 위치·원인·영향 범위 식별 | 사본의 월간·연간 단위 혼용을 찾고 영향을 받는 표를 짚는다. |
| What-if와 직접 수정 | 새 조건에서 예측하고 확인 | 1,000명일 때 바뀔 값을 먼저 예측하고 사본의 계산 결과와 비교한다. |
| 팀원 인수인계 | 지식이 다른 사람에게 전달됐는지 확인 | 다른 팀원이 남겨진 근거와 계산 방법으로 새 조건의 비용표를 작성한다. |

연습에서는 원문과 근거를 읽고 먼저 시도한 뒤 단계별 힌트를 받는다. 독립적인 적용 능력을 확인할 때는 자료 열람은 허용하고, 팀이 합의한 범위에서 에이전트의 답안 생성 없이 작은 변경과 검증을 수행한다. 자기 확신도는 추가 확인 대상을 찾는 참고 정보로 사용한다. AI가 만든 문항과 정답 근거는 검토자가 확인하고, 최종 검토·승인 판단은 배정된 사람이 한다.

## 구현과 GUI·HCI 인수인계

- **Work**에서 정확한 버전과 근거 위치를 참조하고, **Review**에서 과제·응답·피드백을 관리하는 방향부터 검토한다. 지식 부채 항목의 소유 모듈은 수명주기와 조회 요구를 확인해 결정한다. 승인 기록과 공개 증명서 연동은 기존 Approval·Certificate·Verification 경계를 따른다.
- **데이터 후보**는 버전 참조, 범위, 제기자, 담당자, 질문·영향, 보완 근거, 확인자·확인 결과다. 상태 후보는 열린 질문, 확인 대기, 해결, 재확인 필요다. 답변·평가·해결 확인은 각 회차와 판단 대상을 추적할 수 있게 한다. 이후 상세 데이터 설계에서는 키, 다중도, 저장 제약을 명시한다.
- **첫 화면 흐름**은 작업 상세에서 질문 남기기 → 이해 과제에서 근거 보기·답변 → 검토/인수인계에서 미해결 질문과 다음 행동 보기다. 이미 있는 화면과 [UI 가이드](ui/DESIGN.md)를 활용한다. 영향이 큰 부분만 과제로 요청해 팀의 검토 부담을 제한한다.
- **경계 조건**으로 자기 승인 금지, 신규 버전 승인 미상속, 승인·철회의 이력 보존을 확인한다. 승인 후에 발견한 질문은 새 항목으로 연결해 당시 스냅샷을 보존한다. 에이전트 기록을 연동할 때는 작성자가 확인한 발췌·링크와 실행 결과를 근거로 남긴다. 공개 QR에 비공개 답변·근거·에이전트 대화가 노출되지 않도록 하고 출처 파일에도 작업 권한을 적용한다.
- **첫 구현 후보**는 기존 PDF 시연 한 건에서 근거 연결, 설명, 조건 변경, 팀원 확인을 끝까지 잇는 것이다. AI 자동 문항 생성, 에이전트 기록 통합, 지식 검색, 파일·블록 간 영향 추적은 그 흐름을 평가한 후 범위를 결정한다.

### 점검 시나리오

| 상황 | 관찰할 결과 |
| --- | --- |
| 작성자가 답은 제시했으나 원본 근거를 찾지 못함 | 검토자가 빠진 근거를 지정하고, 피드백에서 해당 질문으로 돌아갈 수 있다. |
| 작성자가 설명했으나 팀원이 직접 적용하지 못함 | 작성자 답변과 팀원 확인 결과를 개별 기록하고 미해결 질문을 계속 볼 수 있다. |
| 팀원이 피드백 이후 다른 조건에서 적용에 성공함 | 당시 버전·근거·확인자가 기록되며 이전 시도도 조회된다. |
| v2에서 근거 문단 또는 계산 조건이 변경됨 | 해당 항목이 재확인 대상으로 표시되고, v1 검토·승인 이력을 조회할 수 있다. |
| 다른 팀이 같은 지식을 새 작업에 재사용하려 함 | 원래의 버전·조건·권한을 확인하고 달라진 조건은 다시 검증한다. |
| 외부 공개 링크 또는 권한을 잃은 팀원이 접근함 | 허용된 공개 요약이나 접근 제한 상태만 표시하며 비공개 근거를 제공하지 않는다. |

HCI 평가에서는 기존 고정 문항과 작업물 맞춤 설명·적용 과제를 비슷한 난이도의 작업에 비교한다. 작성자의 근거 설명과 검증 정확도, 검토 소요 시간, 후속 팀원의 수정 성공 여부·소요 시간·원작성자에게 물어본 횟수를 각각 기록한다. 가능하면 두 조건의 순서를 교차하고 동일한 채점 기준과 자료 사용 조건을 적용한다. 과제 수와 승인 연동은 이 결과를 보고 정한다.

연구 결과의 적용 범위와 인용 자료는 [연구 근거](knowledge-debt-research.md)에서 확인한다.
