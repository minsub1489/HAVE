# HAVE 유스케이스 상세 조건

2026-10-28. 수정 원본은 `use-cases.json`이다. 이 문서는 `uml/export_contracts.py`로 생성한다.

유스케이스 개요 · [상태·다중도 검토](uml/state-and-multiplicity.md)

현재 로컬 MVP의 계약이다. 미구현 계정/서버/서명 요구를 구현 완료로 해석하지 않는다. 모든 쓰기 결과는 원자적 저장 성공 후 확정한다.

## UC-01 · 작업·PDF·AI 사용 신고 등록

참여 역할: 작성자

연관 제약: R01, R02, R03, R07, R09, R10

### 사전 조건

- 작성자 시연 역할, 유효 PDF 20 MiB 이하·필수 신고·위험 입력
- 기존 작업 대체 시 현재 시연의 단일 작업 저장 범위 확인

### 정상 결과·사후 조건

- Work 1개에 첫 Version 1개·Review 1개·빈 GateResponse 3개·Evaluation 0개
- Approval/Receipt 0개, 등록 감사 기록; commit 후 성공 표시

### 대안·예외

- 입력/저장 실패는 새 등록을 성공으로 표시하지 않음

## UC-02 · 이해 과제 답변·재제출

참여 역할: 작성자

연관 제약: R02, R03, R04, R07

### 사전 조건

- 대상 버전 미승인, 작성자 역할, 대상 답변 슬롯 미제출·비어 있지 않은 답변
- 수정 요청 후에도 새 Review나 슬롯을 만들지 않음

### 정상 결과·사후 조건

- 기존 3개 슬롯에 제출; 해당 슬롯 현재 평가 초기화
- 마지막 제출이면 returned 해제 후 상태 재판정; 승인 자동 생성 없음

### 대안·예외

- 부분 제출은 작성 중 또는 치명 오류에 따른 수정 요청
- 저장 실패는 제출 전 상태 유지

## UC-03 · 결과물·답변 검토 / 수정 요청

참여 역할: 검토자

연관 제약: R02, R03, R04, R05, R09, R10

### 사전 조건

- 검토자 역할·미승인 버전·평가 대상 답변 제출됨
- 수정 요청은 세 답변 제출 및 사유 필요; 현재 평가와 과거 스냅샷 구분

### 정상 결과·사후 조건

- 현재 평가는 답변 슬롯당 0..1개, 점수 0..2·근거·치명 오류 기록
- 수정 요청 성공 시 ReviewRound 1개 추가(현재 상한 1000), 답변 재제출·현재 평가/체크/메모 초기화

### 대안·예외

- 낮은 점수만으로 자동 반려하지 않음
- 회차 상한·저장 실패는 검토 변경 취소

## UC-04 · 특정 버전 최종 승인

참여 역할: 검토자

연관 제약: R02, R03, R04, R07, R08, R09, R10

### 사전 조건

- 검토자 역할, 기존 Approval 0건 (철회된 승인도 기존 승인에 포함)
- 세 답변·평가 근거·5/6 이상·치명 오류 없음·returned 해제
- 체크 4개·최종 메모·저장 가능·revision 일치

### 정상 결과·사후 조건

- 같은 저장 성공으로 Approval 1건·Receipt payload 1건·감사 기록 생성
- Review·답변·평가·기여 스냅샷 고정, 이 버전의 검토·승인 절차 종료

### 대안·예외

- 조건 미달/저장 실패: Approval/Receipt 0건 유지
- 충돌: 최신 기록 검증·재확인, 자동 재승인 없음
- 운영 비동기 서명 미구현이며 현재 1:1과 혼합하지 않음

## UC-05 · 새 버전 등록

참여 역할: 작성자

연관 제약: R01, R02, R03, R04, R06, R07, R09, R10

### 사전 조건

- 작성자 역할·변경 사유·유효 입력, PDF/신고/위험 중 실제 변경
- 버전 수는 현재 스키마 최대 10000개

### 정상 결과·사후 조건

- Work의 Version +1, 새 Review 1개·빈 답변 3개·현재 평가 0개·승인 0개
- 이전 버전·승인·철회·감사 기록 보존; 기존 버전의 상태를 초기화하지 않음

### 대안·예외

- 이전 recordId를 새 버전에 다시 연결 가능하나 자동 복사·자동 승인 아님
- 입력/저장 실패는 버전 수 증가 없음

## UC-06 · 승인 철회·사유 기록

참여 역할: 검토자

연관 제약: R07, R08, R09, R10

### 사전 조건

- 검토자 역할·철회 가능한 최근 Approval 1건 존재·미철회·사유 있음

### 정상 결과·사후 조건

- 같은 Approval에 철회 시각/사유 추가, 감사 저장
- Approval/Receipt 수는 각각 1건 유지, 같은 버전 재승인/철회 취소 없음

### 대안·예외

- 저장 실패는 미철회 상태 유지; 대상 없음/이미 철회는 거부
- 후속 버전 존재와 철회는 동시 가능

## UC-07 · 승인 요약 확인 / 선택 파일 비교

참여 역할: 검증자 / 수신자

연관 제약: R07, R08

### 사전 조건

- 요약 형식 유효; 실제 서명 검증 기능으로 해석하지 않음
- 로컬 동일 승인 ID 유무로 최신 효력 확인 범위 결정

### 정상 결과·사후 조건

- 공개 요약과 로컬 확인 범위 표시; 파일 선택 시 SHA-256 비교
- 읽기/비교는 Version·Review·Approval·Receipt를 새로 생성하지 않음

### 대안·예외

- 다른 기기에서는 발급 당시 요약·현재 효력 미확인
- 파일 미선택은 일치 미확인, 형식 오류는 오류 표시

## UC-08 · 기여 근거 수집·연결

참여 역할: 작성자

연관 제약: R02, R04, R05, R06, R07, R09, R10

### 사전 조건

- 작성자 역할·미승인 대상 버전·유효 JSON·미리보기/확인
- 버전 내 recordId 중복 제거 후 신규 기록 존재·합계 최대 100개

### 정상 결과·사후 조건

- 버전별 기여 사본 연결; 같은 원본 recordId는 다른 버전에서도 재사용 가능
- 현재 Review는 1개 유지, ReviewRound 1개 추가·평가/체크/메모 초기화, 제출 여부·returned 유지

### 대안·예외

- 모두 중복·기여/회차 상한·대상 변경·저장 실패: 새 연결/회차 없음
- 승인 후 연결은 새 버전에서만 가능, 기여 JSON은 승인 명령 아님

## UC-09 · 증명서·버전·승인 이력 조회

참여 역할: 작성자, 검토자

연관 제약: R01, R02, R05, R07, R08, R09, R10

### 사전 조건

- 해당 로컬 작업 존재; 내부 검토 근거와 공개 요약을 구분

### 정상 결과·사후 조건

- 작업·버전·현재 검토·과거 회차·승인·감사 이력 조회
- 재조회/재다운로드는 새 승인이나 새 Receipt 발급이 아니며 다중도와 상태 변화 없음

### 대안·예외

- 실제 계정 권한 검사는 미구현; 시연 역할을 인증으로 설명하지 않음
