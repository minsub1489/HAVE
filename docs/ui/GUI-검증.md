# HAVE 사용자 GUI 검증 기록

2026-11-16 · Chrome · 작성자 GUI 추가 범위

## 결과

- `npm run build`: 기존 HumanProof HTML과 `prototype/HAVE_사용자_GUI.html` 생성 통과.
- `npm run check`: 기존 웹·저장소·확장 및 새 GUI JavaScript 구문 검사 통과.
- `npm test`: 27개 통과. 기존 도메인·확장 17개, 사용자 모델 10개.
- `node --test --experimental-test-coverage tests/*.test.cjs`: 사용자 모델 `user/model.js`의 줄 99.23%, 분기 89.36%, 함수 100% 실행. UI 전체의 커버리지 수치가 아니다.
- `npm run test:user:browser`: 실제 Chrome에서 12개 사용자 시나리오 통과, 페이지 오류 0개.
- `npm run test:browser`: 기존 웹 흐름과 Chrome 확장 팝업 모의 API 회귀 검사 통과. 실제 확장 설치·툴바 권한 동작은 이번에 수동 점검하지 않았다.
- `git diff --check`: 공백 오류 없음.

브라우저 테스트는 환경에 이미 제공된 Playwright-core와 설치된 Chrome을 사용했다. 개발 의존성이나 컴퓨터별 절대 경로를 프로젝트에 추가하지 않았다.

로컬 서버 진입과 공통 스크립트 응답 200, `.git` 접근 404, 인코딩된 상위 경로 접근 403을 확인했다. 새 모델은 10개 테스트를 먼저 추가해 미구현 오류로 실패하는 것을 확인한 뒤 구현했고, 이후 모두 통과했다. 테스트 단계와 구현 단계의 로컬 변경 기록을 보존한다.

## 보안·범위 검토

사용자 입력은 HTML 삽입 전에 이스케이프한다. 파일 크기를 읽기 전에 검사하고 PDF 확장자·헤더 및 20 MiB 상한을 확인한다. SHA-256은 실제 파일 바이트에서 계산한다. 공유 저장소의 기존 기본 이름은 유지하며 새 화면은 별도 저장소를 사용한다. 작성자 GUI에 승인·철회 명령은 없으며 공개 화면에는 제한된 요약만 렌더링한다. 로컬 미리보기 서버는 루프백에 바인딩하고 사용자 화면·기존 공통 스크립트 경로만 제공한다.

전체 PDF 구문·악성 문서 분석, 실제 계정/서버 권한, 서버 전달·자동 문항/채점·전자서명은 구현 범위 밖이다. 승인 예시는 시연 자료이며 서버의 현재 승인 효력을 확인했다고 표시하지 않는다. 별도 기기와 기존 검토자 시연의 데이터 자동 연동은 없다. 지식 연결·인수인계 과제는 후속 설계 범위다.

실제 사용자 5명 대상 사용성 평가, 전면적인 WCAG 적합성 감사, 보조공학·다른 브라우저·인쇄 결과의 전수 검사는 실시하지 않았다. 여기의 결과는 구현·브라우저 검증 기록이며 사용자 연구 결과가 아니다.

## 테스트 진행 근거

`tests/user-model.test.cjs`를 먼저 추가하고 모델 파일이 없는 상태에서 실패를 확인했다. 이후 등록·제출·버전 규칙을 구현해 10개 모델 테스트를 통과시켰다. 파일 동일성·버전 승인 미상속·공개 필드 제한을 검사하며 단순 렌더링 복제 테스트는 사용하지 않는다. 실제 화면은 별도의 브라우저 시나리오로 확인했다.
